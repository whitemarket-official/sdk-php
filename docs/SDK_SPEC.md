# WhiteMarket SDK: cross-language specification and delivery plan

Identical in all seven SDK repositories: `whitemarket_sdk_php`, `whitemarket_sdk_golang`, `whitemarket_sdk_js`,
`whitemarket_sdk_ts`, `whitemarket_sdk_python`, `whitemarket_sdk_csharp`, `whitemarket_sdk_rust`.
Change it in one repository, copy the change to the other six in the same working day.

API facts live in [`WHITEMARKET_API.md`](WHITEMARKET_API.md). This file defines **what every SDK must look like**.
A language may deviate only where its idioms require it, and records the deviation in its own `docs/DEVIATIONS.md`.

PHP is the reference implementation. On a conflict between this spec and the PHP code, the spec wins and the PHP
code gets fixed.

## 1. Two layers in every SDK

```
+-------------------------------------------------------------+
| High-level client (hand-written, stable, idiomatic)         |
|  WhiteMarketClient: auth, market, buying, deals, selling,   |
|  inventory, orders, wallet, profile, store, exports, live   |
+-------------------------------------------------------------+
| Generated layer (from schema/partner.graphql, never edited) |
|  types, enums, inputs, one typed operation per root field   |
+-------------------------------------------------------------+
| Transport (hand-written): HTTP, auth headers, errors, retry |
+-------------------------------------------------------------+
```

### 1.1 Generated layer

- Source: `schema/partner.graphql` (SDL) + `schema/partner.introspection.json`, both fetched from
  `https://api.white.market/graphql/partner` by introspection. Never hand-edited.
- Operation documents: `graphql/operations/query/<field>.graphql` and `graphql/operations/mutation/<field>.graphql`,
  one per root field, produced by the operation generator (1.2). Hand-written overrides in
  `graphql/overrides/<query|mutation>/<field>.graphql` replace the generated file of the same name.
- Codegen tool per language turns schema + operations into typed code under a dedicated path
  (`src/Generated/`, `generated/`, `Generated/`...). Every generated file starts with a "DO NOT EDIT, generated by ..." header.
- Generated code is **committed** so users install the package without running codegen.
- Generated public surface: all object/input/enum types of the schema, plus a client with one typed method per operation
  (`marketList(variables)`, `MarketList(ctx, vars)`, `market_list(...)`, ...), plus `execute(document, variables)` for raw documents.
- Enums are generated with an "unknown value" fallback so a new server value does not break deserialization.
- Deprecated root fields (`profile_steam_api_key`) are excluded. Deprecated input fields stay (nullable) but are marked deprecated in generated docs.
- `make codegen-check` (CI) regenerates into a temp dir and fails on any diff.

### 1.2 Operation generator (identical across languages)

A small Node.js script `tools/codegen/generate-operations.mjs` using the `graphql` npm package, with a lockfile, in every
repository. Same script, same output, byte-for-byte in all seven repos. Algorithm:

1. Load `schema/partner.graphql`.
2. For each root field of `PartnerQuery` and `PartnerMutation`, sorted by name, skipping deprecated:
   - Operation name: PascalCase of the field (`market_list` -> `MarketList`, `auth_token` -> `AuthToken`).
   - Variables: one per argument, same name, same type, same default value.
   - Selection set: built from the return type by the rules below.
3. Selection rules:
   - Scalars and enums: all non-deprecated fields.
   - Object fields: recurse until max nesting depth `D` (config, default 3 levels below the root field); at the limit, select only `id` if present (`__typename id` for an interface field, so the response still names the concrete type), otherwise skip the field.
   - Connections (`*Connection`): `edges { cursor node { ... } } pageInfo { hasNextPage hasPreviousPage startCursor endCursor } totalCount`, node selected with the same rules.
   - Interfaces and unions: `__typename` plus `... on <Type> { ... }` for every possible type, in schema order.
   - Every object type that is selected in more than one place gets a named fragment `<Type>Fields` in `graphql/fragments/<Type>.graphql` holding only the type's non-deprecated scalar and enum fields. Object fields stay inline next to the spread, because the same type is selected at different depths and a fragment cannot vary by depth.
   - Fields with required arguments are skipped (they cannot be selected without inputs).
4. Validate every document against the schema (`graphql.validate`) and against server limits: depth <= 11, estimated complexity <= 300
   (1 per field, multiplied by `first` default 1). Violation -> fail with the operation name and a hint to add an override.
5. Write files with LF, sorted fields, 2-space indent, trailing newline. Write `graphql/operations/CHECKSUMS` (sha256 per file).
   Repos compare `CHECKSUMS` with the PHP reference repo to prove parity.

Real limits are checked by an opt-in live smoke test (8.3), because the server's complexity formula may differ from the estimate.

### 1.3 Transport

- One configurable HTTP client injected by the user, defaulting to the idiomatic one:
  PHP PSR-18 + PSR-17, default Guzzle (`guzzlehttp/guzzle ^7.9 || ^8.0` + `guzzlehttp/psr7`) with preconfigured
  timeouts; any PSR-18 client can be injected (then the SDK cannot set timeouts and logs one notice), Go `*http.Client`, JS/TS global `fetch` (injectable),
  Python `httpx` (sync and async), C# `HttpClient` (works with `IHttpClientFactory`), Rust `reqwest` (async; `blocking` behind a feature).
- Headers: `Content-Type: application/json`, `Accept: application/json`, `Accept-Encoding: gzip`,
  `User-Agent: whitemarket-sdk-<lang>/<version> (<runtime>/<runtime version>)`, `Authorization: Bearer ...`
  (or `X-partner-token` for `auth_token` only).
- Timeouts: connect 10 s, request 30 s (configurable). Export downloads: no total timeout, idle timeout 60 s.
- Cancellation: Go `context.Context`, C# `CancellationToken`, JS/TS `AbortSignal`, Python `asyncio` cancellation / timeout,
  Rust futures drop, PHP timeouts only.
- Response body size limit for GraphQL (default 32 MiB) to stop a runaway response.
- Debug logging hook: PSR-3 / `slog` / `console`-like logger option / `logging` / `ILogger` / `tracing`.
  Headers `Authorization`, `X-partner-token` and `cf_connect` query values are **always** redacted, request bodies of
  `auth_*` and `profile_token_set` are never logged.

### 1.4 Retry policy

| Request | Retried automatically | On |
|---|---|---|
| GraphQL query | yes, max 3 attempts total (configurable) | network error before a response, 429, 500, 502, 503, 504 |
| GraphQL mutation | **never** | (see buy reconciliation, 3.3) |
| Export GET | yes, max 3 | network error, 5xx, 429 |
| SSE / WS connect | yes, unlimited by default with cap | any disconnect |

Backoff: exponential, base 500 ms, factor 2, cap 30 s, full jitter. A 429 or 503 with `Retry-After` (seconds or
HTTP-date) is not retried: the SDK throws `RateLimitError` / `ServiceUnavailableError` with `retryAfter` at once and
the caller decides when to try again (owner decision 2026-10-31); the SDK never waits for a server-chosen time. On
other statuses the header is ignored. 401 on any request: refresh the access token once and replay once (also for mutations,
because 401 means the request was rejected before execution).

"Never" for mutations includes resends by the HTTP client library: a mutation is sent on a connection that is not
reused and is closed afterwards, unless the library documents that it never resends a request on its own (libcurl
resends on a dead kept-alive connection; see the PHP SDK, ADR 0002, `GuzzleClientFactoryTest`).

### 1.5 Errors

One hierarchy per language (names adapted to idiom: `Exception` in PHP/C#, `Error` in JS/TS/Rust/Go, `...Error` in Python):

```
WhiteMarketError                         base, never thrown directly
 +- TransportError                        DNS, TLS, connect, timeout, body read
 +- HttpError(status, body excerpt)       non-2xx not covered below
 |   +- BadRequestError        400
 |   +- AuthenticationError    401 after one refresh+replay; also invalid Partner Token
 |   +- RateLimitError         429, retryAfter?
 |   +- ServerError            5xx
 |       +- ServiceUnavailableError 503, retryAfter?
 +- GraphQLError(errors[], partialData?)  200 with errors; each error: message, path, locations, category
 |   +- NotFoundError          category ends with ".not_found"
 +- PurchaseOutcomeUnknownError(customId) buy reconciliation found nothing
 +- MutationOutcomeUnknownError(operation) a money-moving mutation failed ambiguously (section 3.8)
 +- DecodeError                           unexpected JSON shape
 +- ExportError                           export download/parse failure
 +- LiveConnectionError                   SSE/WS protocol or auth failure
```

- Branch on `category`, never on `message`. Known categories are constants in `ErrorCategory` (start with
  `market.product.not_found`; extend as the backend confirms them).
- Error messages never contain tokens or request bodies.
- `NotFoundError` is thrown at once: a "not found" answer is never retried (owner decision 2026-10-31).
- `HttpError` body excerpt is safe to log. It is at most 512 bytes of valid UTF-8 (invalid bytes become U+FFFD; the
  limit holds after the replacement). Credential markers, any case: `token`, `secret`, `passw`, `authorization` /
  `authorisation`, `cookie`, `api_key` / `api-key` / `apikey`, `jwt`, `credential`, `session`, `bearer`, `basic`, `eyJ`,
  `cf_connect`. A string (only its first 512 bytes are read) is cut after its first marker, and `***` is appended when
  anything followed. The marker is searched in the string as given and again after each pass of JSON string unescaping
  (`\\`, `\"`, `\/` and `\u0020`-`\u007F`; each escape is one unit read left to right, so `\\u0074` stays `\u0074`),
  cutting at every stage it appears in, until a pass changes nothing. A JSON object or array body (at most 1 MiB, depth
  at most 64) is redacted by structure: every key is redacted as a string, the value under a key that holds a marker
  becomes `"***"` whatever its type, every other string value is redacted as a string, integers beyond 64 bits stay
  exact (as strings), and the result is re-encoded compactly without escaping `/` or non-ASCII. Any other body is
  redacted as one string. A regex or decoder failure yields an empty excerpt, never unredacted text. Not detected, by
  design: a secret with no marker before it in the same string, including one whose marker is only in a sibling value
  (`{"name":"Cookie","value":"..."}`). Shared test cases: `tests/unit/Errors/BodyRedactorTest.php` of the PHP SDK.
- Go: sentinel + typed errors usable with `errors.Is/As`. Rust: `thiserror` enum + `#[non_exhaustive]`.

## 2. Configuration

```
WhiteMarketClient(
  partnerToken?: secret string        // preferred: SDK exchanges it via auth_token
  accessToken?: secret string         // alternative: caller manages JWT
  tokenProvider?: TokenProvider       // full control (custom refresh, auth_steam_jwt, shared cache)
  tokenStore?: TokenStore             // where the cached JWT lives; default in-memory
  baseUrl, graphqlPath, exportBaseUrl, sseUrl, wsUrl
  httpClient, timeouts, retry policy, logger, userAgentSuffix
  buyReconciliation: { delay = 15s (allowed 10-20s), attempts = 3, interval = 5s }
)
```

`WhiteMarketClient.fromEnv()` reads `WHITEMARKET_PARTNER_TOKEN` (and optional `WHITEMARKET_BASE_URL`). Nothing else from env.

Credential options are exclusive: exactly one of `partnerToken`, `accessToken`, `tokenProvider` is given, otherwise
construction fails; `tokenStore` is accepted with `partnerToken` only (a caller's `tokenProvider` owns its storage, a
fixed `accessToken` has nothing to store). An injected `httpClient` is used as is for queries and mutations: the SDK
cannot set its timeouts and logs one notice saying so; the caller is responsible for it not resending requests
(section 1.4). `fromEnv()` lets `WHITEMARKET_BASE_URL` replace only the base URL of the other options. The checks use
the language's argument-validation error.

### TokenStore

Interface `get() -> {token, expiresAt}?`, `set(token, expiresAt)`, `clear()`. Implementations: in-memory (default);
PHP PSR-16 adapter; others: documented interface, users bring Redis etc. Multi-process deployments share a store so
that N workers do not each call `auth_token`.

## 3. High-level API (language-neutral names; adapt case to idiom)

All list methods have two forms: one page (`list*` returning `Page<T> {items, endCursor, hasNextPage, totalCount}`) and
an auto-paginating iterator (`iterate*`: PHP generator, Go `iter.Seq2[T, error]`, JS/TS async iterator, Python sync and async
iterators, C# `IAsyncEnumerable<T>`, Rust `Stream<Item = Result<T>>`). Iterators request the next page lazily.

### 3.3 buying

| Method | GraphQL |
|---|---|
| `buying.buyProduct(productId, maxPrice?, opts)` | `market_buy(id, maxPriceInput)` |
| `buying.buyCheapest(app, nameHash, opts{phase, maxPrice, deliveryPromise})` | `market_buy(appIdNameHashInput, maxPriceInput)` |
| `buying.buyByAssetId(app, assetId, maxPrice?, opts)` | `market_buy(appIdAssetIdInput, maxPriceInput)` |

Common `opts`: `customId?` (generated UUIDv4 if absent, max 100 chars validated client-side), `tradeUrl?` (`link`, buy to a third party).
Return `BuyResult { deal: Deal, customId, reconciled: bool }`.

Reconciliation (exact algorithm, all languages):

```
send market_buy once
if response is a deal -> return
if response is GraphQLError -> throw it (business rejection, the deal was not created)
if 400/401(after refresh)/429 -> throw (request was rejected, no deal)
if 5xx / timeout / transport error after the request may have been sent:
    sleep(reconciliation.delay)
    repeat reconciliation.attempts times:
        deal = deal_item(customId) ; if found -> return reconciled
        deal = deal_history_item(customId) ; if found -> return reconciled
        sleep(reconciliation.interval)
    throw PurchaseOutcomeUnknownError(customId)
```

Reconciliation rules (they refine the algorithm above):

1. Which failures reconcile: every failure of `market_buy` except `GraphQLError` (the deal was not created, but see
   rule 6), 400, 401 (after the transport's one refresh and replay) and 429. Explicitly included: `DecodeError` (a 2xx
   with an unreadable body, or a deal that cannot be mapped), every other `HttpError` (5xx incl. 503, unexpected
   statuses) and `TransportError`, without telling a failure before sending from one after it. An extra lookup is
   cheap; a wrong "no deal" causes a double purchase.
2. A failed lookup (any error, not only `NotFoundError`) counts as "not found in this attempt". The last lookup error
   is kept on `PurchaseOutcomeUnknownError.lastLookupError`; the `market_buy` failure is the cause. A failing lookup
   never turns into "no deal".
3. A `customId` given by the caller must be 1..100 characters; the empty string is rejected client-side (a lookup by an
   empty id is meaningless).
4. The not-found category of a deal lookup is unknown (WHITEMARKET_API.md open question 6); rule 2 makes the SDK
   independent of it.
5. `buyCheapest` takes `maxPrice`, `phase`, `deliveryPromise` as separate named arguments plus the shared `BuyOptions`
   (`customId`, `tradeUrl`); languages without named arguments mirror the split with an options object.
6. A 200 with errors on a nested path, or with a non-null `market_buy` in `data`, means the purchase ran: reconcile it.
   A rejection is: no `market_buy` data and every error path empty or exactly `[market_buy]`. Residual: a root-path
   error raised after the server committed the deal still reads as a rejection; telling those apart needs the
   backend's category catalogue (WHITEMARKET_API.md open questions).
7. Every buy form takes an optional `maxPrice` (`Money`) and sends it as `maxPriceInput`; null sends nothing. The
   currency is validated as for `buyCheapest`. A listing's price can change between reading it and buying it; the cap
   makes the server refuse a dearer purchase (`market.product.not_found_in_specified_price`, a `GraphQLError`, no deal
   [observed 2026-11-02 with `id`; `appIdAssetIdInput` not tried]) instead of taking whatever price holds then.

`deliveryType` on `market_buy` is deprecated and not exposed.

### 3.4 deals

| Method | GraphQL |
|---|---|
| `deals.get(idOrCustomId)` | `deal_item`, falls back to `deal_history_item` on not-found; returns a unified `Deal` with `isArchived` |
| `deals.statuses(ids)` | `deal_buyer_statuses`, chunks ids by 300, preserves request order, merges |
| `deals.listAsBuyer(statusesWith?, statusesWithout?)` | `deal_buyer_list` |
| `deals.listAsSeller(...)` | `deal_seller_list` |
| `deals.history(filter, page)` / `deals.iterateHistory(filter)` | `deal_history` |
| `deals.requestCancel(id)` | `deal_request_cancel` (buyer, after seller does not send for 30 min; check `isCancelByBuyerSupported`, `cancelByBuyerNeedWait`) |
| `deals.reportOfferSent(idOrCustomId, offerId)` | `deal_steam_offer_sent` |
| `deals.cancelSendingOffer(idOrCustomId, reason, comment)` | `deal_cancel_sending_offer`, comment validated: <= 255 chars, `^[a-zA-Z0-9 _-]*$` |
| `deals.holdBalance(currency)` / `deals.holdBalances()` | `deal_balance_hold`, `deal_balances_hold` |
| `deals.waitFor(idOrCustomId, until, opts{timeout, pollInterval=5s, live?})` | polls `deal_buyer_statuses` (seller deals: rule 12); if a live connection is passed, wakes up on deal events and re-checks |

`DealStatus` helpers (from the table in WHITEMARKET_API.md section 4): `isInProgress`, `isFinal`, `isSuccessful`
(`COMPLETED`), `isFailed`, `isReversed`, `isExchanged`, `awaitingTradeProtection(deal)` (`EXCHANGED && isTradeProtected`).
Ready-made `until` predicates: `offered`, `exchangedOrCompleted`, `completed`, `final`.

Rules for `deals`:

1. Reference resolution for queries: a string in UUID form is looked up as `id` first, then as `customId` (a customId
   is often a UUID: the SDK generates UUIDv4 ones); any other string only as `customId` (sending it as `id: Uuid` is a
   validation error). Each key tries `deal_item`, then `deal_history_item` on not-found; a failure that is not a
   not-found propagates at once; when every key is not found the last not-found is thrown. Empty is rejected
   client-side.
2. Mutations that take `idOrCustomId` (`reportOfferSent`, `cancelSendingOffer`) never "try id, then customId"
   (mutations are sent once). A non-UUID reference is sent as `customId`. A UUID-shaped one is resolved with `get()`
   first (queries) and the mutation is sent once with the `id` found; a not-found there means nothing was sent.
3. `statuses(ids)` returns a map keyed by the requested string, in request order; ids the server does not return are
   absent (no error); a duplicate is sent once and returned once. Chunking by 300 is applied after the deduplication.
4. `waitFor` raises `DealWaitTimeoutError(idOrCustomId, lastState, timeout)` (not in 1.5). Default timeout: none. A
   deal the server does not report yet counts as "not yet" (a new deal needs a moment to become visible). The first
   poll is immediate; a timeout of 0 polls exactly once; `pollInterval` must be finite and > 0, `timeout` null or
   finite and >= 0. Elapsed time is wall-clock. Waking up on live events (`opts.live`) is deferred to the live module.
5. Every `until` predicate also matches a final status (`isFinal`), so a wait never outlives a failed or reversed deal
   and the caller checks the status of the returned state. Consequence: `completed` and `final` match the same states
   (`COMPLETED` is final).
6. `QUEUED` is not in the public schema: it can be read (`DealStatus.QUEUED`) but not sent in a status filter; the SDK
   rejects it client-side before any request.
7. A requested key matches a state when it is UUID-shaped and equals the state's `id` without regard to case (RFC
   9562), or equals the state's `customId` exactly (a customId is a free-form `String`, WHITEMARKET_API.md 4: folding
   its case could attribute one deal's state to another whose customId differs only in case). Deduplication for
   sending is exact: two spellings of one UUID are both sent and the server decides; each requested spelling is a key
   of the result.
8. `waitFor` caps the last sleep at the remaining timeout and polls once more at the deadline before raising. The
   timeout bounds the waiting between polls; a poll already in flight (its query retries per section 1.4 and the
   request timeout) may finish after it, so the call can return or throw up to one poll's duration after the timeout.
9. `requestCancel` accepts a deal id (UUID) only; anything else is rejected client-side before any request.
10. A mutation by `idOrCustomId` checks that the resolved deal matches the reference (`id`, or `customId` exactly;
    case-insensitive for the UUID form) before sending; a mismatch is a decode error and nothing is sent.
11. A deal in progress exposes `receiverTradeUrl` (`MarketDeal.receiverTradeUrl`) as a secret, null for null / empty
    and for an archived deal: a MANUAL seller sends the item's `assetId` to it [docs 6-skins-sell], and the URL carries
    the buyer's trade token (same handling as `Profile.steamTradeUrl`, section 3.9 rule 1).
12. `deal_buyer_statuses` returns no row for a deal where the caller is the seller [observed 2026-11-02: a SEMI sale
    gave 0 rows while `deal_item` returned it]. When the reference is not in the answer, `waitFor` reads the deal with
    `deals.get` (`deal_item`, then `deal_history_item`) and keeps using `get` for the rest of the call. A not-found
    answer of both is "not there yet", like an absent status (rule 4).

### 3.5 selling

| Method | GraphQL |
|---|---|
| `selling.list(item, price, opts{deliveryType=SEMI, deliveryPromise, lifetime})` | `market_new` (item = inventoryId or assetId) |
| `selling.listMany(items[], opts)` | `market_new_multiple`, returns per-item results |
| `selling.reprice(productId, price)` / `selling.repriceMany(items)` | `market_edit`, `market_edit_multiple` |
| `selling.remove(productId)` / `selling.removeMany(ids)` | `market_remove`, `market_remove_multiple` |
| `selling.setLifetimeForAll(seconds)` | `market_lifetime_all`, validates >= 600 |
| `selling.myProducts(filter, page)` / `selling.iterateMyProducts(filter)` | `market_my` |

`lifetime` validated client-side: 60 .. 31536000 seconds. `AUTO` delivery type is rejected client-side with a clear error (server rejects it anyway).
Batch inputs larger than a configurable chunk size (default 100, confirm with backend) are chunked; results re-indexed to the caller's order.

Rules for `selling`:

1. Item reference by format: a UUID is an inventory id (`list`, `listMany`) or a listing id (`repriceMany`); digits
   (1..20, a 64-bit Steam asset id kept as a string) are an asset id. Anything else is rejected client-side before any
   request. `reprice`, `remove` and `removeMany` take listing ids (UUID) only.
2. The single selling mutations (`market_new`, `market_edit`, `market_remove`, `market_lifetime_all`) have no
   idempotency key: each is sent once, never retried, and an ambiguous failure (5xx, network error, unreadable
   response) propagates as is, documented as "the outcome is unknown; check `myProducts()`". No reconciliation.
3. Batch result model: `BatchItemResult{index (position in the caller's list), outcome Succeeded|Failed|Unknown|NotSent,
   product, errorCategory, errorMessage}`. `Succeeded`/`Failed` are the server's `isCreated`. A request (chunk) that
   fails stops the batch: its items are `Unknown` (ambiguous failure) or `NotSent` (the server rejected it before
   running it: the classification of section 3.3 rule 6), later chunks are `NotSent` and never sent, earlier chunks
   keep their results, and the call raises `BatchIncompleteError(results)` with the failure as its cause. An item the
   server leaves out of its answer is `Unknown`; the remaining chunks still go out and the error is raised at the end.
   The call returns normally only when every item has a server-reported outcome. A product that cannot be mapped
   leaves `product` empty and does not change the outcome.
4. `MarketProductResult.index` is read as the 0-based position within the chunk (schema doc: "Position in request").
   Not confirmed by the backend: question for the backend, together with the maximum batch size. An `index` outside
   the chunk or repeated cannot be matched; the mutation already ran, so the chunk is `Unknown`.
5. The chunk size defaults to 100 and is configurable at client creation (at least 1).
6. Listing options reject `AUTO` and a `lifetime` outside 60..31536000 at construction; `setLifetimeForAll` rejects
   less than 600. `deliveryType` is always sent (default `SEMI`).
7. Rows are cross-checked against the requested item where the product carries its identity; a mismatch makes the
   chunk `Unknown`.
8. A batch GraphQL error is a rejection (`NotSent`) only when the response has no `data` key AND every error has no
   path: a request error (parse, validation) is raised before execution and omits `data` (GraphQL spec, October 2021,
   7.1.2). `data: null`, or an error at the root field, means execution started (a batch resolver can fail part-way),
   so the chunk is `Unknown`. Single mutations keep section 3.3 rule 6. Residual: a 2xx other than 200 with errors and
   no `data` is also read as a request error; the API documents only 200 for success.

### 3.6 inventory

`inventory.list(filter, page)` / `inventory.iterate(filter)` (`inventory_my`), `inventory.refreshFromSteam()` (`inventory_update`).

1. `refreshFromSteam()` returns nothing for now. The API returns the full person; a later version may return the
   profile model once `profile.get()` exists (widening `void` is backward compatible for callers).
2. `InventoryFilter.sort` reuses the market product sort (the API input type is the same `MarketProductSortInput`).
3. Non-CS2 inventory items (unknown `__typename`) are skipped in pages, like product items.

`orders.create(app, nameHash, price, quantity, opts{float range, phase, tradeUrl})`, `orders.edit(id, price, quantity, tradeUrl?)`,

### 3.8 wallet

`wallet.balance(currency)`, `wallet.balances()`, `wallet.deposits()`, `wallet.withdrawals()`, `wallet.transactions(filter, page)` + iterator,
`wallet.transfers(page)` + iterator, `wallet.credit()` (max/used/available in one call: three fields in one document),
`wallet.takeCredit(money)`, `wallet.transfer(to, money)`.

1. `credit()` is one raw query document with the three root fields (typed per-operation overrides hold one root
   field), so it is a query and is retried as one.
2. `transfer` and `takeCredit` are sent once. A clean rejection (HTTP 400/401/429, a GraphQL error of the root field
   with `data` null) propagates as its own error. Any other failure is `MutationOutcomeUnknownError(operation)`, so a
   caller never mistakes it for a rejection and sends money twice; its message names the method and where to check
   (`wallet.transfers()` / `wallet.credit()`) and carries no amount or id.
3. `transfer(to, amount)` takes a person id or a Steam id unchanged (the format is undocumented); an empty value or one
   with control characters is rejected before any request.
4. Names: models `Deposit`, `Withdrawal`, `WalletTransaction`, `WalletTransfer`, `Debt`, `Credit`, `PersonSummary`;
   enums as in the schema in the language's idiom (`WalletMethodEnum` is `WalletMethod`, `MarketDealActionType` is the
   existing `DealAction`); the filter and the sort are `WalletTransactionFilter` and `WalletTransactionSort`.
5. A root-path or pathless GraphQL error with `data: null` on `transfer` / `takeCredit` is read as a rejection (as
   `market_buy`, section 3.3 rule 6), so a server that fails after committing reports a clean error; telling business
   rejections from post-commit failures needs the backend's category catalogue (WHITEMARKET_API.md open question 1).

### 3.9 profile and store

`profile.id()`, `profile.get()`, `profile.setTradeUrl(url)`, `profile.steamProxy()/setSteamProxy(proxy, ttl)/deleteSteamProxy()`,
`profile.setSteamToken(payload, ownProxyRequired, ttl)/checkSteamToken()/deleteSteamToken()`,
`profile.setEmail/confirmEmail/resendEmailConfirmation`, `profile.linkReferrer/changeReferrerCode`,
`store.get()`, `store.edit(input)`. Steam token payload and proxy credentials are secrets: redacted in logs.

Profile rules:

1. Secrets: the proxy and the token payload are taken as the language's secret type (`setSteamProxy(proxy: Secret,
   ttl)`, `setSteamToken(payload: Secret, ownProxyRequired, ttl)`), the parameters are marked sensitive, and the plain
   value is revealed only when the request body is built. `steamProxy()` returns a secret (or null for null / empty)
   and `Profile.steamTradeUrl` is a secret (null for null / empty): the trade URL carries the trade token.
   `setTradeUrl(url)` takes a plain string with a sensitive parameter.
2. `checkSteamToken()` returns the server's Int unchanged (nullable); the API does not document its meaning.
3. `ttl` is passed through unchanged and not validated on the client; the API documents no unit.
4. `ownProxyRequired` defaults to false and is always sent (the server default is false, so this is equivalent).
5. Every profile mutation is sent once and never retried; failures propagate as they are (no money moves, so no
   "outcome unknown" error). `get()`, `id()` and `steamProxy()` are queries and follow the retry table.
6. `Profile` fields: id, registeredAt, locale, email, isEmailConfirmed, canBuy, canSell, canDeposit, canWithdraw,
   isKycVerified, hasPartnerToken, ordersAutoActivate, deliveryPromise (the existing `DeliveryPromise`), steamId,
   steamName, steamLevel, steamAvatarMedium, steamAvatarFull, steamRegisteredAt, steamTradeUrl, inventoryUpdatedAt,
   discountPercent, discountActiveTo, sellBannedUntil, vacationUntil, level, points, leftPoints, percent (string as
   sent: the format is undocumented), referralsCount, inviterCode, referrerCode, referralTag, countryCodeOfResidence,
   countryCodeOfCurrentLocation, isAchievementsEnabled, isSkinTranslationEnabled, isMcBattlePassEnabled,
   tradingCompetitionStat (position, topLevel). `setEmail`, `confirmEmail` and `resendEmailConfirmation` return the
   same `Profile`. `Locale` is a new enum with an unknown fallback.

Store rules:

1. `store.edit(settings)` takes `StoreSettings` with every field optional (a field left out is not sent): avatar,
   banner, customAvatar, storeName, isAchievementsPublic, isFavoritesPublic, isItemsOnSalePublic, isStoreNamePublic,
   isTradeHistoryPublic. Avatar and banner are enums with an unknown fallback on the read side. No client-side
   validation (the API documents no limits).
2. `customAvatar` is the base64 encoded image, sent as `encodedCustomAvatar`. The multipart `customAvatar` upload is
   not supported by an SDK that sends JSON only.
3. `store.get()` is a query and follows the retry table; `store.edit()` is sent once and never retried, failures
   propagate as they are (no money moves).
4. An achievement parameter is `{name, value}` with `name` an enum (`AchievementCondition`, unknown fallback) and
   `value` a boolean (`AchievementBooleanParam`) or a string (`AchievementStringParam`). The two members share the
   response name `value` with different types, so the selection aliases them (`booleanValue`, `stringValue`;
   `graphql/overrides/`). A union member the SDK does not know, and a null entry, are skipped; a null achievements
   list is an empty list.

### 3.10 exports (no auth, separate client usable standalone: `ExportClient`)

| Method | Does |
|---|---|
| `exports.prices(app=730, window?, opts)` | downloads + parses prices JSON (small, ~21k rows) -> `PriceList` |
| `exports.streamPrices(...)` | streaming iterator over price rows |
| `exports.streamProducts(app=730, window?, format=json)` | **streaming** iterator over product rows (millions) |
| `exports.meta(kind, app, window?, format)` | parses `.meta.json` -> `ExportMeta {file, dataAsOf, generatedAt, items}` |
| `exports.download(kind, app, window?, format, destination)` | raw download to file/stream for callers who process it themselves |
| `PriceList.get(marketHashName, paintIndex)` / `PriceList.allPhases(marketHashName)` | lookup keyed by `(market_hash_name, paint_index)` |
| `affiliateLink(marketProductLink, referralCode)` | appends `ref` |

- `window`: enum `ALL | MINUTES10 | HOUR1 | HOURS12 | HOURS24` -> URL suffix `"" | .10min | .1hour | .12hours | .24hours`.
- Conditional GET: optional cache (ETag + Last-Modified) -> returns `NotModified` instead of re-downloading.
- `maxAge` option: fetch meta first, raise `StaleExportError` (subclass of `ExportError`) if `now - dataAsOf > maxAge`.
- Normalization: all ids (`asset_id`, `class_id`, `instance_id`) as strings; prices as exact decimals; `paint_index` as string in both
  feeds; nullable fields nullable; unknown extra fields kept in `extra` map.
- JSON numbers above 2^53 must not lose precision (JS/TS: read numeric tokens as strings via the streaming parser; others: int64/u64 or string).
- CSV supported with the same row models.

Export rules:

1. Export options: base URL (https origin only), connect timeout 10 s, idle timeout 60 s (the longest silence on the
   connection; there is no total timeout), `maxBodyBytes` 64 MiB. `maxBodyBytes` bounds the DECOMPRESSED size of the
   calls that read a whole file (`meta`, `prices`, `streamPrices`); over it the call fails with the transport error.
   `download` is not bounded (it writes to the destination).
2. An export GET follows at most 3 redirects, only to an https URL on the same host and port as the base URL; any other
   redirect is a transport error. It sends `Accept-Encoding: gzip`. It is retried on a network error, 429 and every 5xx
   (500-599; a query keeps its table of 429/500/502/503/504), at most the configured attempts; 429 and 503 with
   `Retry-After` are not retried (section 1.4). Only a 200 is the file (a 304 to a conditional call is `NotModified`):
   any other 2xx (206, 202, 204) is an `HttpError`. A client's own exception, an SDK exception type included, is a
   `TransportError` without a cause (never an answer of the API, never a reason to refresh and replay).
3. The conditional cache holds the `ETag` and `Last-Modified` of a URL, never the body. A conditional call
   (`prices(conditional: true)`) without a cache is an argument error; with one, a 304 returns `NotModified(url)`.
   Validators are stored after a conditional call parsed its 200 response, so a body that failed to parse never makes
   the next call answer `NotModified`.
4. Errors: `ExportError` is an abstract parent with `GeneralExportError` (the destination could not be written) and
   `StaleExportError` (`dataAsOf`, `maxAgeSeconds`). Statuses other than 200 and network failures of an export GET are
   the `HttpError` hierarchy and `TransportError`, as for GraphQL; a body that is not the expected JSON is
   `DecodeError` with a path like `prices[3].price`.
5. `app` is the Steam app id as an integer (730), validated 1..2^31-1. `PriceRow`: `marketHashName`, `price` (USD
   `Money`), `marketProductLink`, `marketProductCount`, `cheapestAssetId` (string), `cheapestFloat` (decimal or null),
   `paintIndex`, `paintSeed` (strings), `inspectLink` (an empty string becomes null), `extra` (every unknown key, raw).
   A float token in an id field is a `DecodeError` (the precision is already lost).
6. `affiliateLink` accepts only https links on `white.market` or a subdomain (no port, no credentials) and sets or
   replaces the `ref` query parameter (percent-encoded, last), keeping the fragment.
7. Decoding is bounded per step, not only per body: the compressed body is fed to the inflater 1024 bytes at a time and
   deflate expands a byte by at most 1032, so one step yields at most 1024 * 1032 = 1,056,768 decoded bytes (about
   1 MiB). A reader that checks its size limit before it keeps a chunk therefore holds at most the limit, never the
   limit plus a step. For exports the body must be complete: an identity body with `Content-Length` has exactly that
   many bytes (one value, or several identical values; absent: no check; any other value such as `+1000` or
   `1000, 999` is a transport error), a gzip body reaches its end marker, and data after the end of the gzip stream (a
   second member, trailing bytes) is a transport error (GraphQL responses keep ignoring it). `download` writes through
   a private temporary file of its own next to the destination, renamed over it on success.
8. `ProductRow`: `productId`, `marketHashName` (`name_hash`), `price` (`Money` in the row's `currency`; an unknown
   currency is the unknown enum variant), `category` (item category enum or unknown; a row whose category is null is
   skipped by `streamProducts`, the server sends a few such rows, WHITEMARKET_API.md 8; rows keep their file index,
   so error paths and iterator keys count skipped rows), `type`, `subtype` (raw strings
   or null), `classId`, `instanceId`, `assetId` (digit strings), `float` (decimal or null), `paintIndex`, `paintSeed`
   (strings or null; numbers in the file), `phase` (raw string or null), `deliveryType` (`auto|semi|manual` -> the
   delivery type enum, compared upper-cased; unknown variant otherwise; null when absent), `deliveryPromise`
   (`10min|1hour|12hours|24hours` -> `MINUTES10|HOUR1|HOURS12|HOURS24`; unknown variant otherwise; null when absent),
   `inspectLink` (null or an empty string becomes null), `extra` (every unknown key, raw).
9. `streamProducts` sends its requests (meta for `maxAge`, then the file) when called, so a status other than 200
   fails at the call; the body is parsed as it arrives, one row in memory, with no `maxBodyBytes` bound. A row that
   fails to decode or a body that breaks off fails at that row of the iteration, after the rows before it. Stopping
   the iteration closes the connection.
10. JSON: the body must be a top-level array (an object, a scalar or an empty body is `DecodeError` at `products`); a
    syntax error or a cut-short array is `DecodeError` at `products[<index of the row being read>]`, without server
    bytes in the message. A row over 128 KiB of text is `DecodeError` at its index, with every parser, so one hostile
    row cannot exhaust memory (decoded values take far more memory than the text); a parser that cannot see row
    boundaries may read a small, fixed read-ahead past the limit before it refuses the row.
11. CSV (RFC 4180, `,`, `"` with `""`, CRLF or LF, a UTF-8 BOM ignored): the first line is the header and names the
    columns with the JSON keys; columns are matched by name, not position; an empty value is null; every value is a
    string (ids, paint index and seed as digit strings); an empty line is skipped. No header, an empty or repeated
    column name, a record whose field count differs from the header, a body that ends inside a quoted field or a
    record over 128 KiB is a `DecodeError`. The header naming the JSON keys is an assumption until the backend confirms
    it (WHITEMARKET_API.md 11): a different header fails loudly (missing field), never maps columns wrongly.
12. A language SDK may offer faster optional JSON parsers behind an option (PHP: `JsonStreamDecoder`, ADR 0006);
    every one gives the rows above and never rounds an id: one that cannot keep an integer beyond the 64-bit range
    fails that row with `DecodeError`; one refuses a row nested deeper than 511 levels (512 with the enclosing list) with `DecodeError`. The option type tells whether a parser is usable in this runtime
    (PHP: `JsonStreamDecoder::isAvailable()`), so a caller can choose before building the options. On a broken
    body two parsers may differ by one row in what they deliver before the failure and in its index.

### 3.11 live (SSE and WebSocket)

```
live = client.live(transport = WS (default) | SSE, opts)
live.subscribeProducts(handler)          // market_products_updates
live.subscribePersonal(handler)          // #<personId>; server-side subscription, no profile_id call
live.on(eventType, handler) / async iterator of events
live.poll(timeout) -> event | null       // pull API (synchronous languages)
live.connect() / live.close()
```

- Typed events: `ProductAdded`, `ProductEdited` (fields optional, partial updates), `ProductRemoved`,
  `DealInitiated`, `DealOffered`, `DealNeedConfirmation`, `DealExchanged`, `DealCompleted`, `DealExpired`, `DealCancelled`, `DealHold`,
  `UnknownEvent { type, channel, rawContent }`. Product events carry `stickers` and `keychains` as raw lists and
  `price` as money in USD (the message has no currency field; WHITEMARKET_API.md 11). Deal events carry `steamId`
  (`deal_steam_id`), never logged by the SDK.
- A malformed message of a known type (missing required field, wrong scalar type) becomes `UnknownEvent` plus an
  `onError` call; the stream continues.
- Envelope decoding handles `message` as string or object; WS frames split on `\n`.
- Personal channel: the server subscribes `#<personId>` (and `broadcast`) on connect; SDKs do not send a subscribe
  for it and recognise personal channels by the leading `#`. A `105 already subscribed` reply to any subscribe counts
  as success.
- Reconnect forever by default (optional attempt cap): full jitter, 0.5 s base, 20 s cap, attempt counter reset after
  60 s connected; resubscribe all channels. Idle deadline: connect reply `ping` + 10 s, reset by any message; answer the
  server `{}` ping with `{}` when the connect reply has `pong: true`. The server ping interval is clamped to 300 s.
- Close/disconnect codes: 3000-3499 and 4000-4499 reconnect with the backoff; 3500-3999 and 4500-4999 are terminal
  (3500 is the token rejection below). A code outside all four ranges (WebSocket 1000, 1001, 1006, ...) also reconnects
  with the backoff, but at most 5 consecutive times: the 6th in a row ends the session with `LiveConnectionError`
  (code + reason). That counter resets only after a connection stayed up 60 s, not after a connect reply; closes of the
  Centrifugo ranges neither count nor reset it. `maxReconnectAttempts` (when set) applies to every reconnect.
- Reconnect timing: a `Retry-After` can only lengthen a backoff, never shorten it (capped at 300 s). A reconnect that a
  server message asks for (SSE resubscribe, the scheduled token refresh) is immediate only when the connection being
  left stayed up 60 s; otherwise it is a counted backoff attempt, so a server cannot make the session spin. The
  personal channel is never subscribed by the SDK (see above).
- TLS only: live connections use `wss` (WebSocket) and `https` (SSE); the base URL is https-only, so plain `ws` / `http`
  cannot be configured through the public API.
- Close and disconnect reasons are passed through as server text (not redacted), reduced to printable ASCII and cut to
  128 bytes. Callers branch on the close code, never on the reason.
- A handler exception propagates out of the call that dispatched it (`poll()`, `run()`, the event iterator, `waitFor()`);
  the connection stays open. It is not routed to `onError`, which receives non-fatal problems only.
- Token: a fresh token before every connect; when the connect reply `ttl` says under 10 minutes are left, refresh the
  JWT and reconnect (both transports). Error 109 or close code 3500 (or an SSE 401) trigger one refresh + reconnect; a
  second one in a row is terminal (authentication error). Close code 3005 (token expired), the `ttl` rule and the
  scheduled refresh share ONE refresh per streak (a streak ends when a connection stayed up 60 s); after it 3005 still
  reconnects with the backoff but without another refresh. So at most two refreshes per streak: one of these plus one
  authentication rejection. A token provider that cannot renew does not make the session loop.
- Lifecycle callbacks: `onConnecting`, `onConnected(reconnected)`, `onDisconnected(reason)`, `onError`. Messages sent
  during a reconnect are lost (no offsets): `reconnected = true` tells the user to resync via GraphQL.
- `deals.waitFor` accepts an optional live session: it waits with `poll()` instead of sleeping and fetches the GraphQL
  state early when a deal event for the same deal arrives.
- WS implementation: official Centrifugo client where one exists for the language (Go `centrifuge-go`, JS/TS `centrifuge`,
  Python `centrifuge-python`); otherwise a minimal own implementation of the Centrifugo JSON protocol (connect, subscribe,
  ping/pong, push) over the language's WebSocket library. SSE: own small parser over the HTTP client (no browser `EventSource`
  dependency except in browser builds of JS/TS).
- Live events are hints. Business decisions use GraphQL state (`deals.statuses`) after an event.

## 8. Security requirements

- Secrets (Partner Token, JWT, Steam token payload, proxy credentials) wrapped in a secret type that does not print its value
  (`__toString`/`String()`/`toString`/`__repr__`/`ToString`/`Debug` -> `***`).
- Credential fields of responses (`AuthTokens.accessToken`, `WalletDeposit.airwallexSecret`, any string field whose
  name holds, in any case, `token`, `secret`, `passw`, `authorization` / `authorisation`, `cookie`, `api_key` /
  `api-key` / `apikey`, `jwt` or `credential`) decode into that secret type, never a plain string.
- Errors carry no credential in any attached data either: `DecodeError` holds the JSON path and the reason, never the
  response. Where the runtime records call arguments in stack traces (PHP `getTrace()`), every parameter that holds a
  secret, response data or operation variables is excluded from them (PHP: `#[\SensitiveParameter]`, enforced by a
  static check because PHP does not inherit the attribute). Shared test cases: `tests/unit/Generated/GeneratedClientTest.php`
  of the PHP SDK (a malformed sibling of a credential field).
- TLS verification always on; no option to disable it in the high-level API.
- No logging of request/response bodies by default; debug mode redacts as in 1.3.
- Decompression limits on export downloads (configurable max decompressed size for non-streaming calls).
- Untrusted data: live messages and export rows are parsed, validated, never `eval`ed or used to build URLs to other hosts.
- `SECURITY.md` with a private reporting channel. Dependency audit and secret scanning in CI. Minimal dependency set; each runtime
  dependency justified in `docs/decisions/`.
