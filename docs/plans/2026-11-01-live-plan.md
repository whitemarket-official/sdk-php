## Assumptions

A1-A4 of the design. Plus:

- A5 `phrity/websocket` `Server` is usable as a test fixture server in a child process (same package, no new
  dependency). Check at the start of L3; fallback: a minimal scripted RFC 6455 server in the fixture script.
- A6 A Guzzle `stream` body with `read_timeout` returns an empty read without EOF when a slice passes, so the SSE
  read can enforce its own deadline (replaces the refuted "BodyReader on an endless body", analyze-plan finding 1).
  Checked first in L2b (control + invalid-setup outcome described there).

- A7 `stream_select` on the captured socket resource (L3) is a reliable "data waiting" signal for `wss://`: TLS may hold
  decrypted bytes PHP's buffer already read, so select can say "not readable" while a frame is buffered. Check at the
  start of L3 against the fixture server (control: a frame sent while the client waits is seen within one slice;
  a burst of 1000 small frames in one TCP write is fully delivered without waiting for the next ping). Plain `ws://`
  does not exercise TLS buffering: the check also runs once live (owner, `wss://`). Refuted -> fall back to a
  fixed 1 s Configuration timeout and measure partial-frame loss before deciding (adversarial-verifier, rule 14).

- A5/A7 checked (session 21, spike, phrity/websocket 4.1.0, net-stream 2.4.0, PHP 8.5 and 8.2.35, `ws://` and
  `wss://localhost` with a self-signed cert) [observed]: phrity `Server` works as a child-process fixture
  (`onHandshake` drives the script; raw frames written in one `getStream()->write()`). Capture: override
  `Phrity\Net\StreamFactory::createSocketClient()` returning a `SocketClient` subclass whose `connect()` keeps the
  `SocketStream`; pass the factory as the third `Client` argument. A frame sent 2.5 s into a wait is seen by
  `stream_select` and received intact; 1000/5000/20000 frames in one write are all delivered by "receive only when
  select says readable" on ws and wss (`stream_select` counts PHP's own buffer, `unread_bytes` 5886 after one
  receive); the SDK still checks `unread_bytes > 0` before select as a cheap net. `receive()` returns Ping (no
  auto-pong: the SDK answers) and Close (status + reason, no auto-ack); EOF/RST -> `ConnectionClosedException`;
  idle -> `ConnectionTimeoutException`; an oversize frame with `setMaxReceivedFrameSize` ->
  `ConnectionFailureException`. phrity messages of `BadUriException` and `HandshakeException` contain the full URI:
  map by class only. Accepted: select readable with only part of a frame arrived makes `receive()` block up to the
  idle timeout, so `read($deadline)` may overrun its deadline then (the connection is broken in that case anyway).

## Deviations

- L2b / A6 (2026-11-01): required "an expired read slice returns an empty read" -> fact: Guzzle psr7 throws
  `RuntimeException('Unable to read from stream')` (`vendor/guzzlehttp/psr7/src/Stream.php:266-267`, fread returns
  false) with `eof()` false and `getMetadata('timed_out')` true; the stream keeps working [observed, PHP 8.5.4 and
  8.2.35, guzzle 7.16.1, psr7 2.13.2, fixture `tests/fixtures/servers/sse.php` mode `delayed`] -> owner chose option A:
  a read failure counts as "slice expired" only when `timed_out === true` and `!eof()`, through a new wrapped
  `ClientStream` method; every other failure stays a `TransportException`; a client without that metadata behaves as
  before. Before building on it: adversarial-verifier on the observation (rule 14).
  Verifier (session 21): not refuted on PHP 8.5.4 and 8.2.35 (identity body): slice throws at exactly 1.00 s; no
  byte lost or duplicated across a throw mid-event; FIN gives `read('') + eof`, RST gives a throw with
  `eof === true, timed_out === false` (also right after timed-out slices: the flag resets on the failing read);
  200k-event burst read with 0 throws. Side findings, built into L2b: (a) on a chunked body PHP's dechunk filter
  delays data by up to one slice and `timed_out` stays true on successful reads, so it is consulted only on a failed
  read, never after a successful one; extra event latency up to `readSlice` on chunked SSE is accepted (WS is the
  default); (b) a truncated chunked body ends as a clean EOF, so any EOF on the endless SSE stream is a broken
  connection (`TransportException`), and a partial trailing event is dropped. Not checked: TLS, real server
  (owner live run in L6), half-open peers (covered by the session idle deadline).
