## Deviations

- T1.2: SDK_SPEC 1.2 says "every object type selected in more than one place gets a named fragment". Selections of the same type differ by depth, so `<Type>Fields` holds only the type's leaf fields; nested object fields stay inline next to the spread. Three generated operations violate limits and have overrides: `inventory_my` (complexity 306), `store_my` and `store_edit` (union members share `value` with different types: aliased). Spec text to be clarified (proposal for SDK_SPEC 1.2).
- T1.6: PRs opened with the default `GITHUB_TOKEN` do not trigger CI; optional secret `SCHEMA_SYNC_TOKEN`.
- T1.4: "through a fake transport" -> the HTTP transport is P2, so the smoke test runs through a fake `OperationExecutor`
  (`tests/Support/FakeOperationExecutor.php`), the outer boundary of the generated layer today. Switch to the fake PSR-18
  client in T2.4. Done in T2.4 for the HTTP path only (ADR 0002 "Implementation notes (2026-10-31, T2.4)"); the
  decoding tests of the generated layer keep the fake executor, which is that layer's boundary.
- P1 (PHP 8.1): the generator tests crash PHP 8.1.34 with a use-after-free in `zend_array_destroy` (valgrind;
  reproduced on the official `php:8.1-cli` image without PCOV, opcache or PCRE JIT) in about 2 of 3 runs, only when
  webonyx/graphql-php runs; 8.2-8.5 are stable. PHP 8.1 is security-only upstream, so no engine fix is coming.
  Owner decision (2026-10-31): the generator runs only in our CI, never on a user's machine, so its tests
  (`tests/codegen`, PHPUnit suite `codegen`, `make test-codegen`) run once on `TOOLS_PHP_VERSION` in `make check` and
  the CI `static` job, outside the runtime matrix. The golden output is still executed on every supported version
  (`tests/unit/Generated/GoldenOutputTest.php`).
- P2 (PHP 8.1 + PCOV 1.0.12): with `GoldenOutputTest` in the run, `phpunit --coverage-clover` segfaults (exit 139) in
  5/5 runs while writing the Clover report, after every test passed; without coverage, or without that class, 0/5
  [observed 2026-10-31, local `php:8.1-cli` + pcov image]. Coverage is a gate on the code, not on the runtime, so it runs
  once on `TOOLS_PHP_VERSION` (`make check`, CI `tests` job on 8.5); the matrix and the other CI versions run
  `make test` without a coverage driver. Same engine family as the P1 crash; not hunted further (no 8.1 engine fixes).
- P2 (PHP 8.1, superseded 2026-10-31): plan and ADR 0002 required 8.1 support. `make matrix` segfaulted on 8.1 in the
  unit tests without any extension; the cause is an 8.1 engine double free when generated decoders throw (ADR 0002
  "Amendment 2026-10-31"); P1/P2 above show the same `zend_array_destroy` signature but were not re-checked against
  it. Owner decision: minimum PHP 8.2.
- P2 (Infection): `make infection` through the Docker bind mount crashed with "Too many open files" (Docker Desktop for
  macOS file sharing, 2/2 runs; 0/3 on a container-local copy). The Docker run of the target now works on a copy of the
  tree and copies the reports back (Makefile `INFECTION_IN_COPY`).
- P1 finding: the partner schema hides every implementation of `MarketOrder` / `MarketOrderPublic`, and SDK_SPEC 1.2
  selects only `__typename` plus inline fragments for abstract types, so all order operations select `__typename` only.
  Cause (owner, 2026-10-31): the backend's `config/packages/graphql.yaml` declares `CSGOMarketOrder` and
  `CSGOMarketOrderPublic` in the `types` list of the `api` schema but not of the `partner` schema, so they are not
  reachable in partner introspection. Fix requested in the backend; proposal P4 in
  `docs/plans/2026-10-30-sdk-spec-proposals.md` is on hold. Until then the orders area cannot read order fields.
